# SaveSense AI Development Rules

This project is production quality.

Never generate placeholder architecture.

Always write code as if this will serve millions of users.

Requirements

• Clean Architecture
• SOLID Principles
• DRY
• KISS
• Dependency Injection
• Repository Pattern
• CQRS where appropriate
• Feature-first organization
• Unit Tests
• Integration Tests
• XML Documentation
• Strong typing
• Async everywhere
• Minimal APIs when appropriate
• RESTful API conventions

Never create dead code.

Never duplicate code.

Always explain architectural decisions.

If multiple approaches exist, choose the one used in enterprise software.

When unsure, ask before implementing.

Every completed feature must compile before moving on.

Never skip testing.

Keep commits small.

Always update documentation.

Never hardcode secrets.

Always use configuration files.

Follow Microsoft's C# coding conventions.
